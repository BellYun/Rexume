## 🔍 기술별 설명

### 1. IntersectionObserver 프리워밍 (IO 75vh)
- **설명**: `rootMargin: 75vh`로 설정하여 뷰포트 진입 전에 미리 렌더링 시작
- **효과**: 스크롤 시 즉시 표시, 프리로딩 효과
- **적용 버전**: Opt7, Opt8, Opt9, Opt10, RAF (5개)

### 2. RAF 페인트 안정화 (Double RAF)
- **설명**: 렌더링 완료 후 `requestAnimationFrame`을 2번 호출하여 페인트 동기화
- **효과**: 레이아웃 시프트 감소
- **단점**: 추가 대기 시간 발생 (16-33ms)
- **적용 버전**: Lazy, Opt3, Opt8, RAF (4개)

### 3. Callback Ref 패턴
- **설명**: `useCallback`으로 ref 함수 메모이제이션
- **효과**: 리렌더링 최적화, ref 재생성 방지
- **적용 버전**: Opt3, Opt7, Opt8, Opt9, Opt10, RAF (6개)

### 4. RenderScheduler (K=4)
- **설명**: 동시 렌더링을 최대 4개로 제한
- **효과**: 메모리/CPU 사용량 제어
- **적용 버전**: Opt7, Opt8, Opt9, RAF (4개)

### 5. RAF 배칭
- **설명**: IntersectionObserver 콜백을 rAF로 배칭하여 한 프레임에 묶어 처리
- **효과**: 레이아웃 재계산 감소
- **적용 버전**: Opt7, Opt8, Opt9, Opt10, RAF (5개)

### 6. 우선순위 정렬
- **설명**: viewport 중심 거리 기반으로 가까운 페이지 우선 렌더링
- **효과**: 사용자 체감 성능 향상
- **적용 버전**: Opt7, Opt8, Opt9, RAF (4개)

### 7. Lazy getPage
- **설명**: `getPage()`를 실제 렌더링 시점에만 호출
- **효과**: 초기 로딩 시간 단축
- **적용 버전**: Lazy, Opt10 (2개)

- **적용 X**: Lazy (2위), Basic (4위), Opt3 (5위), Simple (7위)

- **적용 X**: 나머지 모두 하위권

### RAF 페인트 안정화 적용 여부
- **적용 O**: Lazy (2위), Opt3 (5위), Opt8 (6위), RAF (9위)
- **적용 X**: Opt10 (1위), Opt9 (3위), Basic (4위)
- **결론**: 페인트 안정화는 선택적, 제거 시 더 빠를 수 있음

### 스케줄링 최적화 (Scheduler + 배칭 + 우선순위) 전체 적용
- **적용 O**: Opt7 (8위), Opt8 (6위), Opt9 (3위), RAF (9위)
- **결론**: Lazy getPage 없이 스케줄링만으로는 한계

## 🏆 최종 결론

1. **Lazy getPage가 핵심**: 상위 2개 버전(Opt10, Lazy) 모두 적용
2. **RAF 페인트 안정화는 선택적**: 제거 시 더 빠를 수 있음
3. **과도한 최적화는 역효과**: RAF가 모든 기술 적용했으나 최하위
4. **단순함이 최고**: Lazy가 최소 코드로 TBT 1위
5. **복합 최적화는 신중하게**: Opt10처럼 검증된 조합만 사용
